## 1. What this project is

**CityPulse** is a citizen-facing **smart-city civic-issue reporting app**, built as a college CEP project by Aditya (B.Tech CSE, KBT College of Engineering, Nashik). It is a **mobile-first React web app** that runs inside a 430px-wide "phone shell", even on desktop.

Citizens can:
1. Report a civic issue (pothole, garbage, waterlogging, broken streetlight, etc.)
2. Attach a photo and a GPS/map-picked location
3. See nearby hazard alerts and a community map
4. Confirm or deny whether an issue is still present ("community verification")
5. Track their own submitted reports

**Core product principle:** the citizen never picks a government department. They say what they see; the app maps issue type to category and severity internally (`src/lib/issueMeta.ts`).

**Intended flow:** Report → Process → Verify → Alert nearby citizens → Community updates.

**This is NOT** an authority / municipal dashboard. It is only the citizen app.

**Current state: Phase 1 prototype. No backend, no real auth, no real alerts.** All data is mock data plus `localStorage`. The UI labels itself as demo ("Demo civic feed · not live reports", "Prototype login — no real authentication yet").

### PhoneShell behaviour
- Outer: `min-h-dvh bg-surface-dim`. Inner column: `mx-auto w-full max-w-[430px] flex flex-col bg-background` with a soft shadow.
- On every page **except** `/`, the inner column is `h-dvh overflow-hidden`; each page then owns its own scrolling (`<main className="flex-1 overflow-y-auto …">`). The landing page scrolls normally.
- `showTabs` is true when the pathname equals or starts with one of `TAB_ROUTES = ['/home','/map','/report','/reports','/profile','/notifications']`.
- **To add a page with a tab bar, add its path to `TAB_ROUTES`.**

Tabs: Home (`/home`), Community (`/map`), **Report** (`/report`, raised circular FAB, `primary: true`), My Reports (`/reports`), Profile (`/profile`). Active state is path-prefix based. `BellButton` (a `NavLink` to `/notifications` with a red dot) is exported from this file and used by `TopHeader`.

### TopHeader props
`title: string`, `subtitle?: string`, `backTo?: string | number` (string = path, number = history delta like `-1`), `showBell?: boolean` (default true), `right?: ReactNode`.

## 5. Data model (`src/types/report.ts`)

```ts
type Severity = 'High' | 'Medium' | 'Low'

type ReportStatus =
  | 'Submitted' | 'In Progress' | 'Community Confirmed'
  | 'Community Monitoring' | 'Resolved'

type IssueType =
  | 'Pothole' | 'Road Damage' | 'Garbage' | 'Water Leakage'
  | 'Waterlogging' | 'Broken Streetlight' | 'Fallen Tree' | 'Other'

type IssueCategory = 'Road Infrastructure' | 'Waste' | 'Water' | 'Electricity' | 'Other'

type MapFilter = 'All' | 'Roads' | 'Waste' | 'Water' | 'Electricity' | 'Other'

interface Report {
  id: string                 // "CP-1042"
  type: IssueType
  category: IssueCategory
  description: string
  locationLabel: string      // human label, e.g. "College Road, Nashik"
  latitude: number
  longitude: number
  severity: Severity
  status: ReportStatus
  reportedAt: string         // ISO timestamp
  confirmations: number      // community "still present" count
  image: string | null       // data URL (user upload) or Unsplash URL (mock)
  isMine?: boolean           // true → appears in "Your Reports"/"My Reports"
  distanceMeters?: number    // static demo value, not computed
  timeline?: TimelineStep[]
}

interface TimelineStep { label: string; done: boolean; active?: boolean }
interface GeoPoint { lat: number; lng: number }
```

### Issue type → category / severity (`src/lib/issueMeta.ts`)

| Issue type | Category | Default severity | Emoji |
|---|---|---|---|
| Pothole | Road Infrastructure | High | 🕳️ |
| Road Damage | Road Infrastructure | Medium | 🛣️ |
| Fallen Tree | Road Infrastructure | High | 🌳 |
| Garbage | Waste | Medium | 🗑️ |
| Water Leakage | Water | High | 💧 |
| Waterlogging | Water | High | 🌊 |
| Broken Streetlight | Electricity | Low | 💡 |
| Other | Other | Low | 📌 |

`matchesMapFilter(category, filter)`: `'All'` → everything; `'Roads'` → `Road Infrastructure`; otherwise the filter string must equal the category (`Waste`, `Water`, `Electricity`, `Other`).

### Helpers (`src/lib/format.ts`)
- `formatRelative(iso)` → "Just now" / "N minutes ago" / "N hours ago" / "yesterday" / "N days ago" (<7d) / else `formatDate`
- `formatDate(iso)` → `toLocaleDateString('en-IN', {day:'numeric', month:'short', year:'numeric'})`
- `formatCoords(lat,lng)` → `"20.0063° N, 73.7621° E"` (4 decimals; hardcodes N/E)
- `greeting()` → Good morning (<12) / afternoon (<17) / evening
- `formatDistance(m?)` → "" if undefined, `"120m away"`, or `"1.1km away"`

## 6. State management (`src/context/ReportsContext.tsx`)

One React context, `ReportsProvider` (wraps the whole app in `App.tsx`), consumed with `useReports()` (throws if used outside the provider).

**Value shape**
```ts
{
  reports: Report[]
  addReport(input: { type; locationLabel; point: GeoPoint; description; image }): Report
  getReport(id): Report | undefined
  confirmIssue(id, vote: 'present' | 'resolved'): void
  getVote(id): 'present' | 'resolved' | undefined
}
```

**localStorage keys**
- `citypulse.userReports` → `Report[]` created by the user (newest first)
- `citypulse.votes` → `Record<reportId, 'present' | 'resolved'>`

**How `reports` is built:** `[...userReports (excluding ids that collide with mocks), ...MOCK_REPORTS]`, each with `confirmations + confirmOverrides[id]`. So user reports come first.

**`addReport`:** generates id via `nextId` (max numeric suffix across user + mock reports + 1, formatted `CP-<n>`; mocks go up to CP-1042, so the first user report is `CP-1043`), sets `category` and `severity` from `issueMeta`, `status: 'Submitted'`, `confirmations: 1`, `isMine: true`, `distanceMeters: 0`, `description` falls back to `'Citizen-reported civic issue.'`, and a 4-step timeline where the first two steps are done and "Community verification started" is active. Persists to localStorage and returns the report.

**`confirmIssue`:** stores the vote, and adjusts a transient `confirmOverrides[id]` delta: +1 when switching to `present`, −1 when leaving `present`.

## 8. Screens in detail

**Landing (`/`)** — header with logo + "Nashik · demo" pill; a decorative radar-style hero card (static "Pothole (demo)", "Cleared nearby" chips, hardcoded coordinates, hardcoded stat tiles "8 Demo hazards" and "Mock Sample data only"); title "CITYPULSE", tagline "Your city. Your awareness."; two buttons that both go to `/home`.

**Home (`/home`)** — `TopHeader` title is hardcoded "Nashik, College Rd". Shows greeting + "Report an Issue" CTA (`Link` to `/report`), "Nearby Alerts" (reports looked up by `NEARBY_ALERT_IDS`, rendered as compact `AlertCard`s), and "Your Reports" (first 3 where `isMine`) with "View All Reports" link.

**ReportIssue (`/report`)** — 4-step wizard with a step indicator (`Issue`, `Location`, `Evidence`, `Review`). Local state: `step`, `type`, `point` (default `DEFAULT_PIN`), `locationLabel` (default `'College Road, Nashik'`), `description`, `image`, `geoBusy`.
1. *Issue:* grid of 8 `IssueTypeCard`s; Next disabled until a type is chosen.
2. *Location:* `MapView` in `pickable` mode (tap to move pin) + "Use My Location" (browser Geolocation, 8s timeout, high accuracy; falls back to `DEFAULT_PIN` with a "mock fallback" label on error/unsupported).
3. *Evidence:* hidden `<input type="file" accept="image/*" capture="environment">`; image read with `FileReader.readAsDataURL`; description textarea (optional).
4. *Review:* summary rows, then "Submit Report" → `addReport(...)` → `navigate('/reports/<newId>', { replace: true })`.

**ReportDetails (`/reports/:id`)** — "report not found" fallback; otherwise status + severity badges, type, location, photo, Reported date / Severity / Category / Coordinates grid, description, `Timeline` (falls back to a default 4-step timeline if none), `VerificationCard`, and a static "Nearby Citizen Alert" note. Back button uses `backTo={-1}`.

**MyReports (`/reports`)** — filters `reports` to `isMine`. Metric tiles (Total, Active = status ≠ Resolved, Resolved) and a segmented All/Active/Resolved control; empty state text "No reports in this tab yet."

**CommunityMap (`/map`)** — `MapView` over `reports` filtered by chip (`All, Roads, Waste, Water, Electricity, Other`). Tapping a marker opens a bottom sheet (type, severity, location, relative time, status, distance, "View details" / "Close"). Collapsible legend: red = High, amber = Medium, green = "Low / resolved". Changing the filter clears the selection.

**Profile (`/profile`)** — hardcoded demo user **"Aditi Sharma"**, "Citizen · Nashik West", "College Road area (demo profile)". Rows link to notifications / my reports / community map; info note about the "never ask the department" principle; "Sign out" simply navigates to `/`.

**Notifications (`/notifications`)** — the three `NEARBY_ALERT_IDS` reports as tappable cards, with a note that real push notifications come later.

### Shared components worth knowing
- **MapView props:** `reports?`, `selectedId?`, `onSelect?(report)`, `pickable?`, `picked?`, `onPick?(point)`, `center?` (default `NASHIK_CENTER`), `zoom?` (default 14). Uses OSM tiles (`tile.openstreetmap.org`), `CircleMarker`s colored by severity (resolved = `#007d55`, High `#ef4444`, Medium `#f59e0b`, else `#10b981`), a Leaflet `Marker` for the picked point (default icon imported from `leaflet/dist/images/*` and re-created with `L.icon` to fix Vite asset paths), and a `Recenter` child that calls `map.setView` whenever `picked ?? center` changes.
- **StatusBadge / SeverityBadge:** `Record`-based style maps keyed by `ReportStatus` / `Severity`. High severity dot pulses.
- **VerificationCard props:** `confirmations`, `vote?`, `onVote(vote)`. Two buttons: "Yes, still present" (red) and "No, resolved"; shows "N citizens confirmed this issue." plus a thank-you line after voting (local `justVoted` state).
- **Timeline:** `steps: TimelineStep[]`; done = green check, active = blue radio, pending = grey.

## 9. Design system

Tailwind v4, CSS-first: tokens live in the `@theme { … }` block in `src/index.css` and automatically become utilities (e.g. `--color-surface-lowest` → `bg-surface-lowest`, `text-on-surface-variant`, `border-outline-variant`). There is **no** `tailwind.config` file.

Key tokens: `primary #004ac6`, `primary-container #2563eb`, `primary-fixed #dbe1ff`, `tertiary #006242`, `tertiary-container #007d55`, `error #ba1a1a`, `surface #f8f9ff` (layers `surface-lowest #fff` → `surface-highest #d3e4fe`), `surface-dim #cbdbf5`, `on-surface #0b1c30`, `outline #737686`, `outline-variant #c3c6d7`, `severity-high #ef4444`, `severity-medium #f59e0b`, `severity-low #10b981`, `--font-sans: Inter`.

Style conventions: Material-3-inspired light theme, rounded-2xl cards with `border-outline-variant/40`, `active:scale-[0.98]` press feedback, minimum tap targets 44px (`min-h-11`/`h-12`/`min-h-14`), arbitrary px font sizes (`text-[13px]`, `text-[24px]`), `backdrop-blur-md` on sticky bars. `index.css` also forces Leaflet container sizing and `z-index`, and defines a `.hide-scrollbar` utility. **Light mode only** (no dark variant implemented).

## 10. Coding conventions

1. Functional components with destructured props; named exports.
2. Tailwind utility classes only; no CSS modules. Use `cn(...)` from `src/lib/cn.ts` for conditional classes (it is not `clsx` — it only accepts strings/falsy values, no object syntax).
3. PascalCase for component/page files; camelCase for `lib/`, `data/`, `context/` files that export functions/constants (the context file itself is `ReportsContext.tsx`).
4. Use `import type { … }` for types (enforced by `verbatimModuleSyntax`).
5. Navigation: `useNavigate()` for programmatic, `<Link>`/`<NavLink>` for declarative.
6. Single-column mobile layouts only; no separate desktop layout.
7. Pages follow the pattern: root `flex min-h-0 flex-1 flex-col overflow-hidden` → `<TopHeader/>` → `<main className="flex-1 overflow-y-auto px-4 pt-4 pb-4">`.

## 11. Common tasks (recipes)

**Add a page:** create `src/pages/X.tsx` → add `<Route path="/x" element={<X/>} />` inside the `PhoneShell` route in `App.tsx` → if it should show the tab bar, add the path to `TAB_ROUTES` in `PhoneShell.tsx` (and to `tabs` in `BottomTabBar.tsx` if it needs its own tab).

**Add an issue type:** extend `IssueType` in `types/report.ts` → add to `ISSUE_TYPES`, `categoryForType`, `severityForType`, `issueEmoji` in `lib/issueMeta.ts` → add an icon to the `ICONS` record in `IssueTypeCard.tsx` (it is `Record<IssueType, LucideIcon>`, so the build fails until you do).

**Add a report status:** extend `ReportStatus` → add a style to the `styles` record in `StatusBadge.tsx` (also a full `Record`).

**Add a map filter:** extend `MapFilter` → add to `FILTERS` in `CommunityMap.tsx` → handle it in `matchesMapFilter`.

**Connect a real backend:** replace the `localStorage` reads/writes in `ReportsContext.tsx` with API calls while keeping the `Report` interface (`reports` → GET, `addReport` → POST, `confirmIssue` → PATCH/POST). Keep the `useReports()` surface unchanged so pages need no edits.

## 12. Known quirks, gaps and gotchas (verified in source)

1. **Vote counts reset on reload.** `votes` is persisted but `confirmOverrides` (the +1/−1 count delta) is in-memory only, so after a refresh the user's vote is remembered but the displayed confirmation count loses their contribution.
2. **"No, resolved" does not change anything global.** It only records the vote locally; report `status` is never updated by votes.
3. **Map taps don't update the location label.** In the wizard, `locationLabel` stays `'College Road, Nashik'` unless "Use My Location" is used (then it becomes `'Current location'` or a "mock fallback" label). Tapping the map only changes coordinates. There is no reverse geocoding.
4. **Photos are stored as base64 data URLs inside localStorage**, which risks hitting the ~5 MB quota with a few large images (a failed `setItem` would throw inside the state updater).
5. **`localStorage.setItem` is called inside the `setUserReports` / `setVotes` updater functions** (side effects in updaters; harmless but impure, and double-invoked under StrictMode in dev).
6. **"Nearby" is fake.** Home and Notifications use the fixed `NEARBY_ALERT_IDS`; `distanceMeters` is a hardcoded number per mock report (0 for new reports). Nothing uses the user's real position for alerts.
7. **Hardcoded demo strings:** Home header "Nashik, College Rd", Landing stat tiles ("8", "Mock") and coordinates, Profile user "Aditi Sharma". Update these if the demo identity matters.
8. **Auth is fake:** both Landing buttons go to `/home`; "Sign out" goes to `/`. No session state exists.
9. **Mock severities don't always match `severityForType`** (see section 7).
10. **`isMine` drives "Your Reports".** Four mock reports (CP-1042, 1037, 1035, 1012) are flagged as the demo user's; user-created reports are also `isMine: true`, so My Reports shows those plus new ones.
11. **Mock images (Unsplash) and map tiles (OpenStreetMap) and the Inter font need internet.** Offline, markers/layout still work but tiles/photos/font won't load.
12. **Template leftovers:** `src/App.css`, `src/assets/*`, `public/icons.svg`, and the Vite template `README.md` are not part of the product.
13. **No tests exist.** `npm run build` (type-check + bundle) and `npm run lint` are the only automated checks.
14. **The repo's own `CONTEXT.md` references a Windows path (`d:\CEPL\citypulse`)** — that is the author's local machine; in the repo the project root is the repository root.
15. **Single-commit history**, no branches/CI/deploy config in the repo.

## 14. Quick-start for an AI agent

1. `npm install && npm run dev` (Node with npm required; no env vars or secrets are needed).
2. Domain types are in `src/types/report.ts`; business rules (type → category/severity) in `src/lib/issueMeta.ts`; all state in `src/context/ReportsContext.tsx`.
3. Keep changes mobile-first, Tailwind-only, `import type` for types, and keep the `Report` interface stable.
4. Before finishing a change, run `npm run build` and `npm run lint`.
5. Respect the product principle: **the user never chooses a department**.
